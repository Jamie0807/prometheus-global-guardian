---

在最近的项目中我从0到1主导了基于webGL的渲染器引擎的整体重构。

问题根源是原有方案用 DOM Marker 渲染每个点位，数据量超过 1000 时，浏览器频繁触发 Layout 和 Repaint，帧率直接崩到 5fps 以下。

我把它拆成三层解决：第一层是渲染架构，引入 LOD 调度——远景用 GeoJSON cluster 图层交给 GPU 一次性渲染，近景保留 Marker；第二层是增量更新，利用 Mapbox GeoJSON Source 的 diff 机制，从全量替换改为只上传变化部分；第三层是线程分工，把格式转换、去重、坐标过滤拆到 Web Worker，主线程不再感知数据处理，页面交互始终流畅。

---

另外一个是我们要在平台上加 AI 灾害分析。直接调 OpenAI API 无法描述多步骤、有条件分支的流程，各业务线也在重复实现类似逻辑，复用性极差。

所以我主导从零设计了一套 AI 工作流执行引擎，核心难点有三个：一是用注册表模式统一调度异构节点，节点间通过变量插值传递数据，引擎只管按拓扑顺序执行；二是 LangGraph 多分支场景下状态容易污染，通过严格定义状态结构和边条件函数来约束，保证对话历史始终完整；三是本地 Ollama 模型和云端 OpenAI 接口不兼容，加了一层模型适配器，切换模型只改配置不改业务逻辑。

这套引擎最终以 SaaS API 对内开放，集成进了 Prometheus 的 AI 分析模块。
