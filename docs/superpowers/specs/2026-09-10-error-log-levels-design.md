# 前后端错误信息与调试信息分级设计（待确认）

## 需求定位与现状

本次是既有错误处理能力的增量更新，覆盖 React 前端、Express BFF 和 Python 分析服务。当前工作区干净。前端存在直接输出业务数据和异常对象的 console 调用，ErrorBoundary 无环境区分地展示异常和组件栈；BFF 日志入口分散；Python 已使用 logging，但多个模块配置全局日志。

## 方案比较

1. 推荐：统一等级语义和环境配置，各运行时使用轻量日志入口。改造现有输出及错误展示，保留现有接口兼容性，适合当前项目。
2. 仅将 console.log 改成 console.debug：改动少，但不能解决等级过滤、生产错误详情展示和 Python 配置分散问题。
3. 引入集中日志平台：支持跨服务检索，但增加部署与依赖成本，超出本次需求。

## 等级约定

| 等级  | 用途                     | 示例                                     |
| ----- | ------------------------ | ---------------------------------------- |
| debug | 排障细节和开发交互轨迹   | 缓存命中、图表点击、分析状态变化         |
| info  | 正常生命周期中的重要事件 | 服务启动、关键操作完成                   |
| warn  | 可恢复异常或功能降级     | 重试、可选数据源失败、回退基础分析       |
| error | 操作最终失败或未处理异常 | 请求重试耗尽、页面渲染失败、分析接口异常 |

用户取消请求不记录为错误。正常空结果不自动视为警告。避免同一失败在请求层、服务层和组件层重复记录。

## 配置与日志结构

- 前端使用 VITE_LOG_LEVEL，开发默认 debug，生产默认 warn。
- BFF 和 Python 使用 LOG_LEVEL，开发默认 debug，生产默认 info；实现时明确各运行时现有环境变量与默认环境的对应关系。
- 支持 debug、info、warn、error、silent 阈值；无效配置回落到环境默认值。
- TypeScript 提供可测试的日志入口，Python 复用标准 logging 并集中初始化，移除业务模块的 basicConfig。
- 日志包含等级、模块、稳定事件名与必要上下文；沿用现有请求标识，不为本需求另建追踪系统。
- 不输出令牌、凭据、请求头、完整请求或响应正文。优先使用明确允许的上下文字段，异常详情也必须经过脱敏。

## 错误展示与兼容性

- 日志等级不改变用户可见的错误状态、重试和降级行为。
- 用户界面使用可理解且安全的提示；生产环境不展示原始异常、内部路径或堆栈。ErrorBoundary 的诊断详情仅在开发环境可见。
- 保留现有 ServiceError 类型以及 HTTP 状态和错误码契约，不把日志等级混入业务错误码。
- 后端错误响应继续使用安全消息，详细诊断只进入受控服务端日志。
- 排查现有错误展示入口，避免将 responseBody 或原始异常直接显示给用户。

## 实现边界

迁移应用源码中的现有日志调用，按事件实际影响重新分级；覆盖前端、BFF 和 Python API 及分析模块。不增加日志管理界面、外部日志平台、文件轮转或新的业务通知功能。不改变分析算法。

## 验证与执行流程

先为等级阈值、环境默认值、非法配置回落、敏感上下文过滤和生产错误展示编写失败测试，再实现最小改动。复用现有接口测试确认响应契约不变。

实现拆为共享约定、前端改造、BFF 改造和 Python 改造；接口约定稳定后由独立子智能体执行可并行任务，每个任务复核，最后整体复核。

运行 pnpm run lint、pnpm run format:check、pnpm test、pnpm run typecheck:client、pnpm run typecheck:server、pnpm run build、git diff --check；另运行相关组件测试与 Python 测试。记录真实结果，失败先定位根因。未经用户明确要求不暂存、不提交、不推送。
