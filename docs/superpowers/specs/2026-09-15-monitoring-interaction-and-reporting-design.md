# 监控交互、分析与可读报告设计

**日期：** 2026-09-15
**状态：** 已实施并完成验证

## 目标

修复监控首页中已确认的七项体验问题：标题与监控面板对齐、筛选控件视觉统一、监控说明更完整、地图点位可查看详情、数据分析可成功展示、AI 首包前不显示空白气泡，以及保存报告可由普通用户直接阅读。

本轮不引入外部状态库、报表服务或 PDF 生成依赖；现有共享的 `MapStateContext`、Mapbox、FastAPI 与浏览器下载机制继续保留。

## 已确认行为

### 监控首页

- 顶部标题“实时全球环境灾害监控平台与可视化平台”的左边缘与状态面板保持 `16px` 左边距对齐，不再受居中 `max-width` 容器影响。
- “实时环境灾害”改为“实时监测全球环境灾害动态”。
- 灾害类型继续使用原生 `select`，以保持键盘操作、屏幕阅读器和移动端支持；外层容器提供统一的装饰性下拉箭头，箭头不接收指针事件。
- 筛选值、总数和刷新动作的既有数据语义不变。

### 地图点位

地图有两种可见形态，二者都必须有明确交互：

- 聚合点：点击后读取当前聚合集群的展开缩放级别，调用地图放大并飞行至该位置。
- 未聚合单点：点击后显示现有安全 Popup；内容继续通过 DOM 节点写入，不能使用未转义的 HTML。
- 高缩放级别的 HTML Marker 继续显示同一份 Popup 内容。
- 热力图模式不新增 Popup，也不改变现有标记/热力图切换语义。

## 分析服务契约

数据分析页并行请求统计、预测和风险评估。前端会在成功 HTTP 响应中拒绝不满足领域契约的 JSON，不能通过放宽客户端解析来掩盖。本轮以页面当前 100 条灾害数据实测三个本机 FastAPI 接口均返回 200 且可由严格解析器接收，因此截图中的“数据格式异常”应按运行中服务版本或瞬时状态排查。

- FastAPI 的 `/api/v1/statistics`、`/api/v1/predictions` 和 `/api/v1/risk-assessment` 均维持 `{ success: true, data: ... }` 成功信封。
- 当前服务响应已满足客户端领域解析器；后续算法调整仍须确保数值为有限 JSON 数字、不可用值为 `null`、必需对象字段存在。
- 客户端继续拒绝畸形响应，并向用户显示安全、可操作的失败信息；成功响应则正常更新统计、预测和风险评估视图。
- 已以代表性灾害请求实际调用 FastAPI 路由并验证三个核心成功信封，Python 回归也覆盖该路由层行为；后续可补固定跨语言响应样本，防止 Python 算法字段变化再次导致前端“分析失败”。

## AI 流式首包等待态

- 发送问题后，立即保存用户消息并显示既有输入区“AI 正在生成分析结果……”状态。
- 在收到第一个非空文本分片前，不创建助手消息、头像、气泡或闪烁光标。
- 首个非空分片到达时再创建助手消息，并从该内容开始流式更新；光标只在有实际回答文本的流式消息中显示。
- 请求取消、失败或以空内容完成时，不留下空白助手气泡；错误和重试仍由既有错误区呈现。

## HTML 报告

点击“下载报告”生成一个独立 `.html` 文件，而不是 JSON。

- 结构：报告标题、组织与联系人（如填写）、补充说明、生成时间、当前筛选、事件总数、按灾害类型汇总、灾害明细表。
- 明细表包含标题、类型、严重程度、发生时间、来源与说明；缺失字段呈现为“未知”。
- 报告名称经文件名规范化后作为下载文件名；MIME 类型为 `text/html;charset=utf-8`。
- 所有用户输入和外部灾害字段在写入 HTML 前进行文本转义，防止导出文件执行脚本或插入标签。
- 内嵌打印样式使浏览器“打印/另存为 PDF”得到可读文档；本轮不直接生成 PDF。
