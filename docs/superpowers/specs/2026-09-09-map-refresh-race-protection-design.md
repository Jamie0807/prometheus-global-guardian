# 地图自动刷新与请求竞态保护设计

## 目标

为地图灾害数据请求补充统一的刷新生命周期：自动刷新、页面隐藏暂停、恢复可见立即刷新、同筛选条件请求去重、请求取消，以及网络和 Worker 晚到结果的过期保护。

## 范围

- 仅处理 `useHazardData` 调用的 `/api/hazards` 请求及其 hazard worker 清洗结果。
- 继续使用 `config.ui.refreshInterval` 的 5 分钟间隔。
- 手动刷新、首次加载、筛选变化和自动刷新共用同一个刷新入口。
- 补充组件测试并更新项目待优化清单。

本次不改变 BFF 缓存、来源状态契约、AI 流式请求或 Analytics 请求的生命周期。

## 刷新控制器

在 `useHazardData` 内维护以下私有引用：

- 当前请求的 `AbortController`，用于筛选变化、隐藏页面、卸载时取消网络请求。
- 当前进行中请求的 Promise 及其筛选条件，同一筛选条件的手动或定时刷新直接复用该 Promise。
- 单调递增的请求序号，任何异步阶段开始时记录序号，只有仍是最新序号且组件未卸载时才更新状态。
- 卸载标志，防止网络请求或 worker 消息在组件卸载后调用 `setState` 或 `onDataUpdate`。

`refresh` 接收可选的刷新原因。相同筛选条件已有进行中请求时返回该 Promise；筛选条件不同则先取消旧控制器、递增序号，再发起新请求。`fetchHazardFeed` 扩展为接收可选 `AbortSignal`，并传给 HTTP 客户端。

HTTP 客户端保留其独立超时控制器，同时监听调用方 signal 并转发取消到底层 fetch。调用方取消不是超时，不转换为 `ServiceError`，也不触发重试；Hook 将其作为预期生命周期事件忽略。

## 自动刷新与页面可见性

首次地图数据加载完成后创建 5 分钟定时器。`document.hidden` 为 `true` 时：清除定时器，并取消仅由定时器触发的进行中请求。页面恢复可见时：立即执行一次刷新，完成后重新开始 5 分钟周期。

卸载时清除定时器、移除 `visibilitychange` 监听、取消所有进行中请求、终止 worker，并使当前请求序号失效。

筛选条件变化不等待旧请求完成：旧请求立即取消并由新筛选条件请求替代。若浏览器或 mock 在 abort 后仍返回结果，序号检查会丢弃该结果。

## Worker 与状态更新

网络响应获得 hazards 后，worker 清洗也携带请求序号。worker 返回时只有当前最新且组件仍挂载的请求能调用 `setDisasters`、`setSourceMeta` 与 `onDataUpdate`。成功返回空 hazards 仍更新来源元数据和空数据状态；失败或中止不清空已有灾害数据与来源状态。

## 测试与验证

- service 与 HTTP 测试验证调用方取消会中止底层 fetch，且不会被重试或转换为超时错误。
- 组件测试验证相同筛选条件的连续刷新只发出一个网络请求。
- 组件测试验证筛选变化和卸载会中止旧请求，且旧网络或 worker 结果不会覆盖新状态。
- Fake timers 测试隐藏页面暂停周期、恢复可见立即刷新并重建周期。
- 完成后执行 Node 基线、Python unittest、格式检查和 `git diff --check`。

## 边界

刷新间隔不加入用户设置，不做后台刷新，也不引入跨组件请求池。BFF 来源级缓存继续独立工作；前端仅负责发起、取消和接收聚合请求。
