# AI 流式会话生命周期治理设计

状态：待用户确认。范围：既有 AI 助手、浏览器 AI Service、Express AI 路由及流式适配器的增量改造。

## 现状与目标

- `AIChatAssistant.tsx` 在关闭时仅隐藏 DOM；流式请求和 Demo 定时器继续运行。清空对话也未取消请求，旧回调可能改变后续会话的状态。
- 浏览器 Service 逐行解析 SSE，忽略 malformed JSON 和尾部数据，把没有完成标记的 EOF 当成成功。
- BFF 在响应头到达时清除超时，响应体读取和流转发可能无限等待；Responses 的 failed/incomplete 被转换成成功完成标记。
- 本轮保证停止、关闭、清空、卸载能终止整条请求链；区分正常结束、主动取消、超时、协议异常与断流；控制发送历史和上下文规模。

## 方案比较

1. **推荐：会话 Hook + 可取消 Service + BFF 连接生命周期管理。** 覆盖 UI 到上游的完整链路，职责清晰，可分别测试。
2. 仅在组件中加入 AbortController。改动少，但无法修复服务端超时、协议结束和流适配问题。
3. 增加服务端会话存储、断点续传和自动重连。需要 provider 支持续传或事件重放，成本和范围明显更大，留待独立需求。

## 用户行为

- 生成中提供“停止生成”；同步请求锁保证重复点击、Enter 与快捷提问不会发起并发请求。
- 停止、关闭（包括 Escape 和遮罩关闭）、外部将 isOpen 置为 false 时立即取消；保留已有文字并标记“已停止”。重新打开保留历史，允许再次发送。
- 清空先取消，再清除消息与错误；旧请求的 chunk、完成、失败和 finally 均不得影响新会话。
- 卸载取消请求并清理定时器、监听器，卸载后不更新 React 状态。
- 网络断开、超时和协议错误保留部分回答并显示安全提示。提供手动“重试”，使用原请求快照替换该次未完成回答，不重复追加用户消息。
- 不自动重发已开始输出的请求；主动取消不显示失败告警。部分回答不作为完整助手回答发送给下一轮模型。
- 中文输入法组合期间 Enter 不发送。

## 状态与职责

- 新增会话 Hook 持有消息、当前请求 ID、AbortController、同步请求锁和重试快照。状态明确区分 idle、connecting、streaming 与终态 completed/cancelled/failed。
- 每个回调及异步状态更新验证请求 ID；清空、停止、关闭和卸载使旧 ID 失效。消息通过 ID 定位，避免旧 finally 解除新请求锁。
- Service 接收 AbortSignal，统一返回一次完成、取消或失败结果；负责 fetch、SSE 解码、reader 取消/释放和可取消 Demo 延迟。
- UI 负责展示与交互；灾害上下文在发送时生成快照，生成过程中上下文开关或数据变化只影响下一次请求。

## SSE 与 BFF

- 浏览器和 provider 适配器使用增量 UTF-8 解码，支持跨字节字符、跨 chunk 事件、LF/CRLF、注释心跳、多行 data 和最终无换行尾部。
- `[DONE]` 触发一次成功结束，取消后续读取；EOF 无完成标记、损坏 JSON、明确 provider failed/incomplete/error 均报告失败。正常无文本元数据事件可以忽略。
- BFF 输出一致的 Chat Completions 增量、完成标记与不含上游原文的错误事件。失败事件不得转换为 `[DONE]`；流已经开始后不得切换 provider 拼接输出。
- 每个 provider attempt 的现有请求超时覆盖从建立连接到响应体结束的全过程，成功、失败、取消均清理 timer、监听器和流。
- 客户端断开立即 abort 当前上游并停止 fallback；仅响应头发出之前允许现有 provider 降级。正常完成与提前断开日志分别记录，断开不得记为成功 200。
- 使用有背压和错误处理的流转发，销毁源流与转换流时避免未处理 error 或重复终结。

## 请求与用量边界

- 复用 BFF 既有 50 条消息、单条 8000 字符、64 KiB 请求体和上下文字段限制；提取可供浏览器使用的纯常量，服务端保留权威校验。
- 发送模型的历史仅含已完成轮次与当前用户消息，按最近完整轮次裁剪；单条超长输入在发起请求前提示，不静默截断用户问题。
- 灾害上下文仍最多发送最近 8 条，字段按既有长度约束裁剪。序列化后使用 UTF-8 字节数校验总请求体，优先移除最旧轮次，再缩减上下文；当前问题仍无法容纳时明确提示。
- 界面历史在面板生命周期内保留，发送历史裁剪不删除界面消息；异常和取消回答不进入正常模型历史。
- 本轮用单并发、输入预算、全程超时和取消控制调用资源。货币额度、账户计费和跨实例限额需要独立产品策略，本轮不引入。

## 验收与测试

- Service：字节半包、事件半包、CRLF、多行 data、尾部、DONE 后额外数据、缺失 DONE、malformed JSON、失败事件、预取消/读取中取消、reader 释放、Demo 取消。
- Hook/组件：重复发送、停止后立即再发、关闭后重开、清空后重发、卸载、旧回调晚到、部分回答保留、重试快照及不重复用户消息、输入法 Enter、中文 UTF-8 请求体上限。
- BFF：响应头前断开、流中断开、响应体超时、JSON workflow 读取超时、转换器异常、failed/incomplete、终态一次与资源清理；使用模拟上游，不调用真实模型。
- 回归：`pnpm run lint`、`pnpm run format:check`、`pnpm test`、`pnpm run test:component`、前后端 typecheck、build、相关浏览器冒烟及 `git diff --check`。
- 开发完成更新优化清单和测试说明；提交仅在用户明确要求时执行。

## 范围与自审

不修改 Python 分析服务、地图和 Analytics 数据 Hook；不引入新状态库、会话持久化或模型供应商。终态、重试、历史裁剪和取消行为已明确，本设计作为后续任务拆分与验证依据。
